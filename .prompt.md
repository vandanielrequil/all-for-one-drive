# Контекст проекта all-for-one-drive

## Цель

Go-приложение готовит фотографии и видео к резервному копированию, а затем
загружает их на несколько бесплатных хостингов согласно приоритетам.

## Архитектура

- `internal/` — изолированные, потенциально переиспользуемые модули.
- Единственная команда — `cmd/convert-and-upload`: конвертация изображений,
  конвертация видео, затем архивация результатов.
- `all-for-one.config.jsonc` — единый глобальный конфиг с комментариями.
- По умолчанию конфиг ищется рядом с исполняемым файлом (`os.Executable()`).
- Пути в конфиге разрешаются относительно расположения файла конфига.
- Исходные медиафайлы неизменяемы: их нельзя перезаписывать или удалять.
- Не запускать никакие Git-команды, включая команды только для чтения.
- Не писать новые тесты, если пользователь явно этого не попросил.
- Логи: `internal/applog`, формат `модуль - функция - вход`.
- Лог пишется в консоль и в файл `{имя_бинарника}.log` рядом с exe.

## Image converter

- Пакет: `internal/image-converter` (`package imageconverter`).
- Поддерживаемый вход: JPEG, PNG, GIF, TIFF и BMP; результат всегда JPEG.
- Сохраняется дерево поддиректорий и основа исходного имени файла.
- Существующий выходной файл пропускается, а не перезаписывается.
- При превышении `maxDimension` большая сторона уменьшается с Lanczos;
  маленькие изображения не увеличиваются.
- JPEG кодируется стандартным `image/jpeg` с параметром `quality`.
- Для исходных JPEG копируются валидные EXIF APP1-сегменты. Поврежденный EXIF
  не мешает сохранить обработанное изображение.
- Битый или неподдерживаемый файл не останавливает пакетную обработку.

## Video converter

- Пакет: `internal/video-converter` (`package videoconverter`).
- Требует `ffmpeg` в PATH.
- Поддерживаемый вход: MP4, MOV, AVI, MKV, WebM, M4V, WMV, FLV, MPEG, 3GP;
  результат всегда MP4 (H.264 + AAC).
- `maxDimension` — уменьшение только если сторона больше лимита; иначе размер не меняется.
- `quality` (1–100) маппится в libx264 CRF: `51 - quality*0.37` (83 → CRF 21).
- Метаданные копируются через `-map_metadata 0`.
- Исходники не трогаются; существующий выходной файл пропускается.

## Archiver

- Пакет: `internal/archiver`.
- Принимает массив директорий и архивирует каждую отдельно.
- Требует `7z`, `7zz` или `7za` в PATH.
- Формат: 7z без сжатия (`-mx=0`).
- Метод принимает опциональный пароль: пустая строка отключает шифрование,
  непустая включает `-mhe=on` и `-p...`.
- Группы ограничены `maxArchiveSizeMB`; архив проверяется после создания и при
  превышении пересобирается меньшими группами. Один файл больше лимита
  допускается как отдельный архив.
- Имя начинается с имени входной директории и имени первого файла группы.
- Входная директория очищается только после успешного создания всех её архивов.
- Архивы складываются в `archiver.outputDir`.

## Запуск

- Сборка: `go build -o ./bin/convert-and-upload.exe ./cmd/convert-and-upload`.
- Конфиг: `./bin/all-for-one.config.jsonc` рядом с бинарником.
- Другой конфиг: `convert-and-upload.exe -config <путь>`.

## Дальнейшая работа

- Конфиг со временем будет содержать credentials: перед их добавлением нужно
  вынести безопасный пример и исключить локальный конфиг с секретами из Git.
- Модули загрузки не должны зависеть от конкретной CLI-команды.
- Для повторных запусков предпочтительны идемпотентные операции.
- Не менять и не удалять пользовательские исходники даже при ошибках.
